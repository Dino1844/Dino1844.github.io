你已经知道：计算机只认 IP 地址。但没人记 93.184.216.34——我们记 example.com。DNS（Domain Name System）就是把人类可读的域名翻译成机器可读的 IP 地址的分布式、分层数据库。

🎯 本课目标：理解 DNS 的分层查询过程、递归与迭代的区别、常见记录类型、缓存机制，以及 DNS 的安全与隐私问题。

1. 域名空间：一棵倒长的树

DNS 的命名空间是一个树状结构，从根开始向下：

根 (Root)
↓
.com .org .cn .io ...
↓
example.com google.com github.com
↓
www.example.com mail.example.com （子域名）

全球有 13 组根域名服务器（由 ICANN 管理），它们不存储具体域名-IP 映射，只告诉你"去哪个 TLD 服务器找"。13 组听起来很少，但通过 Anycast 技术在全球部署了数千个实例。

2. 递归查询 vs 迭代查询

当你的浏览器需要解析 www.example.com 时，有两种查询模式：

递归查询迭代查询
谁干活？DNS 解析器替你跑完整条链DNS 解析器每次只告诉你"下一步去哪"，你自己接着问
典型场景用户 → 本地 DNS (ISP)本地 DNS → 根 → TLD → 权威
结果返回最终答案返回一个"推荐"（referral）
解析 www.example.com 的完整过程：
你的电脑→递归→本地 DNS (ISP)
本地 DNS→迭代→Root"去 .com TLD 问"
本地 DNS→迭代→.com TLD"去 example.com 权威服务器问"
本地 DNS→迭代→权威 DNS"www.example.com 的 IP 是 93.184.216.34"

关键洞察：你只发了一次递归请求，你的本地 DNS 服务器替你跑了三次迭代查询。这就是分布式系统的优雅之处——每一层只负责自己的那部分数据，查询负载被自然地分摊了。

3. 常见 DNS 记录类型

类型全称值用途
AAddressIPv4 地址example.com → 93.184.216.34
AAAAIPv6 AddressIPv6 地址example.com → 2606:2800:220:1:...
CNAMECanonical Name别名指向www.example.com → example.com（然后再查 A）
MXMail Exchange邮件服务器域名 + 优先级example.com 的邮件发给 mail.example.com
NSName Server权威 DNS 服务器example.com 的 DNS 由 ns1.dns.com 管理
TXTText任意文本SPF（发件人验证）、域名所有权验证
⚠️ CNAME 的限制：CNAME 不能和 MX 或 NS 记录共存——如果 example.com 已经是 CNAME，它就不能同时有 MX 记录。因为 CNAME 的意思是"我不是真的，去查那个名字"，你不可能既"不是真的"又"管邮件"。

4. DNS 缓存 —— 为什么改域名那么慢？

DNS 查询结果被多层缓存，以减少查询延迟和根/TLD 的负载：

  1. 浏览器缓存——Chrome 默认缓存 DNS 1 分钟
  2. 操作系统缓存——nscd 或 systemd-resolved
  3. 本地 DNS 服务器缓存——你的路由器或 ISP 的递归解析器
  4. TTL（Time To Live）——由域名的权威服务器设定，告诉各级缓存"这条记录能缓存多久"（常见值：300 秒 – 86400 秒）

这就是为什么改了 DNS 记录后，全世界要等 TTL 过期才能全部看到新地址——即所谓的"DNS 传播时间"。

5. DNS 安全问题

攻击手法防御
DNS 劫持篡改 DNS 响应，把用户导向钓鱼网站DNSSEC（数字签名验证）
DNS 缓存投毒伪造 DNS 响应注入错误记录到缓存中DNSSEC + 源端口随机化
DNS 隐私泄露ISP 能看到你访问的所有域名DoH (DNS over HTTPS) / DoT (DNS over TLS)
DDoS 放大攻击伪造受害者 IP 发小 DNS 请求，对受害者产生大量响应响应速率限制 + 源地址验证

DoH（DNS over HTTPS）把 DNS 查询藏在 HTTPS 流量里，和普通 Web 流量混在一起。ISP 看不到你在解析什么域名——但代价是 DNS 解析可能比 ISP 的 DNS 稍慢（HTTPS 握手有开销），而且把 DNS 数据从 ISP 转移到了 DoH 提供商（如 Cloudflare、Google）。

📚 补充：DHCP —— "我的 IP 地址从哪来？"

DNS 解决了"知道域名怎么找 IP"，但有一个更前置的问题：你的电脑开机时，自己的 IP 地址是哪来的？答案是 DHCP（Dynamic Host Configuration Protocol）。

DHCP 的四步舞（DORA）

步骤方向消息含义
Discover客户端 → 广播DHCPDISCOVER"这里有人能给我 IP 吗？"（UDP 广播到 255.255.255.255:67）
Offer服务器 → 客户端DHCPOFFER"我有个 192.168.1.100 可以给你，租期 24 小时"
Request客户端 → 广播DHCPREQUEST"好，我要 192.168.1.100"（广播是告诉其他 DHCP 服务器：别给我了）
Ack服务器 → 客户端DHCPACK"成交。加上子网掩码 255.255.255.0，网关 192.168.1.1，DNS 8.8.8.8"

DHCP 给的不仅是 IP 地址，还包括：子网掩码、默认网关、DNS 服务器地址——三样东西缺了哪样都上不了网。这就是为什么路由器通常同时扮演 DHCP 服务器的角色。

租期与续约

DHCP 分配的 IP 有租期（Lease Time），通常是 24 小时。到期前客户端会尝试续约（直接发 DHCPREQUEST 给原服务器）。如果续约失败，IP 被回收。这就是为什么你的手机 IP 可能会变——它换了 WiFi 就拿到新 IP。
