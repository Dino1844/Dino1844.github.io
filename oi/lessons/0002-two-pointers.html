1. 双指针的本质：用两个指针编码搜索约束

回顾 Lesson 0001 的结论：优化的本质是缩小搜索空间。单指针遍历时，我们的搜索空间是一个一维的线；双指针用一个迂回的语法说了一件简单的事：不是所有数对都需要检查。

具体来说，双指针技术的三个底层原理：

原理含义体现
有序性数据被排序后，某个方向上的变化是单调的相向指针：sum 太大→右指针左移
不变量循环每步都保持某个性质成立读写指针：[0, slow) 始终是处理好的区域
剪枝安全性能证明被跳过的候选不可能比已知解更好盛水容器：证明矮柱可以安全放弃
🧠 面试中「看到什么想双指针」：
1. 题目涉及两个位置的关系（两数之和、容器两端）
2. 数据已经有序或排序后不影响答案
3. 要求原地修改数组（in-place）
4. 从两端同时向中间操作（回文串、接雨水）

2. 模式一：相向（对撞）指针 — 完整理论

2.1 模板

// 相向指针通用模板
int l = 0, r = n - 1;
while (l < r) {
    // 根据 nums[l] 和 nums[r] 的关系决定移动哪个指针
    if (/* 条件：通常和 nums[l] + nums[r] 或 min(nums[l], nums[r]) 有关 */) {
        // 更新答案...
    }
    if (/* 应该移动左指针 */) l++;
    else r--;
}

2.2 为什么它是对的：循环不变量论证

📐 相向指针的正确性证明（通用框架）

设问题是：在有序数组中找到满足条件 P 的数对 (i, j)。

声明（不变量）：在 while 循环的每一步开始前，如果存在满足 P 的数对 (i*, j*)，那么一定有 l ≤ i* ≤ j* ≤ r。

初始化：l=0, r=n-1，显然满足。

保持：假设当前满足不变量。当我们根据某个规则移动 l 或 r 时，需要证明被移过的位置不可能是答案的一部分。

关键论证（以 Two Sum 为例）：如果 nums[l] + nums[r] < target，由于 nums 有序，nums[l] + 任何 ≤ nums[r] 的数都 ≤ nums[l] + nums[r] < target。所以 nums[l] 不可能是答案的一部分，l++ 是安全的。

终止：当 l ≥ r 时，搜索空间为空，如果还没找到答案则不存在。

这个证明框架适用于所有相向指针问题。每道题的具体差异只在于「移动哪个指针」的判断条件和对应的安全性论证。

3. 相向指针题 1：Two Sum II — 最纯粹的形式

LeetCode 167. Two Sum II — Input Array Is Sorted
给定一个已排序的数组，找出两个数使它们的和等于 target。返回下标（1-indexed）。

这是相向指针最纯粹的形态：数据天然有序，只需要不断将当前和与 target 比较来移动指针。

vector<int> twoSum(vector<int>& numbers, int target) {
    int l = 0, r = numbers.size() - 1;
    while (l < r) {
        int sum = numbers[l] + numbers[r];
        if (sum == target) return {l + 1, r + 1};
        else if (sum < target) l++;   // 和太小 → 需要一个更大的数 → 左指针右移
        else r--;                        // 和太大 → 需要一个更小的数 → 右指针左移
    }
    return {};
}

复杂度：O(n) 时间、O(1) 空间。对比哈希表解法的 O(n)/O(n)，这在空间上更优。

与 Two Sum (无序版) 的选择：
- 无序 + 返回下标 → 哈希表 O(n)/O(n)
- 无序 + 返回值 → 排序 + 相向指针 O(n log n)/O(1)
- 已排序 → 相向指针 O(n)/O(1)（无需哈希表！）

4. 相向指针题 2：3Sum — 嵌套对撞

LeetCode 15. 3Sum（Hot 100）
找出所有和为 0 的不重复三元组。

3Sum 的思想在 Lesson 0001 中作为「排序创造结构」的例子介绍过。这里从双指针的视角深入分析内层的相向指针是如何工作的。

4.1 结构拆解

// 3Sum = 外层遍历固定第一个数 + 内层相向指针找剩下两个数
sort(nums.begin(), nums.end());
for (int i = 0; i < n - 2; i++) {
    if (i > 0 && nums[i] == nums[i-1]) continue;  // 去重：跳过相同起点
    // ↓ 内层就是 Two Sum II，target = -nums[i]
    int l = i + 1, r = n - 1;
    while (l < r) {
        int sum = nums[i] + nums[l] + nums[r];
        if (sum == 0) { /* 记录 + 去重 */ }
        else if (sum < 0) l++;
        else r--;
    }
}

4.2 去重的正确性论证

去重是 3Sum 最容易出错的点。为什么跳过相同元素不会漏解？

// 外层去重：
if (i > 0 && nums[i] == nums[i-1]) continue;
// 证明：当处理 nums[i-1] 时，已经找到了所有「第一个数为 nums[i-1]」的三元组。
//       nums[i] == nums[i-1]，所以「第一个数为 nums[i]」的三元组 = 已找到的三元组。
//       跳过 nums[i] 不会遗漏任何新三元组。

// 内层去重：
while (l < r && nums[l] == nums[l+1]) l++;
while (l < r && nums[r] == nums[r-1]) r--;
// 证明：找到一个解后，如果第二/第三个数有重复，跳过它们不会遗漏新解，
//       因为固定第一个数后，第二个数确定则第三个也确定。

4.3 时间复杂度分析

外循环 O(n)，内层相向指针 O(n)，总 O(n²)。排序 O(n log n) 不是瓶颈。

空间复杂度 O(1)（不计输出）。这体现了相向指针相比哈希表的一个优势：不需要额外空间。

4Sum 的推广：k-Sum 问题可以用递归固定 + 最内层相向指针的模式解决。k-Sum 的时间复杂度是 O(nk-1)。3Sum → O(n²)，4Sum → O(n³)，依此类推。

5. 相向指针题 3：盛水容器 — 贪心剪枝

LeetCode 11. Container With Most Water（Hot 100）
选两条线使得容器盛水最多。面积 = 宽度 × min(左高, 右高)。

这道题的相向指针与 Two Sum 的核心区别在移动规则：Two Sum 根据 sum 与 target 的关系移动；盛水容器根据两边高度的贪心策略移动。

5.1 完整代码与注释

int maxArea(vector<int>& height) {
    int l = 0, r = height.size() - 1, ans = 0;
    while (l < r) {
        ans = max(ans, (r - l) * min(height[l], height[r]));
        if (height[l] < height[r]) l++;  // 淘汰较矮的边
        else r--;
    }
    return ans;
}

5.2 为什么「淘汰矮的」一定安全？

📐 盛水容器的剪枝正确性证明

设当前指针为 (L, R)，且 h[L] ≤ h[R]（左边更矮）。

断言：以 L 为左壁的任何容器 (L, R')（其中 L < R' < R），其面积 ≤ 当前面积 area(L, R)。

证明：

  1. area(L, R') = (R' - L) × min(h[L], h[R'])
  2. 因为 R' < R，所以 (R' - L) < (R - L)（宽度变小）
  3. 因为 h[L] ≤ h[R]，所以 min(h[L], h[R']) ≤ h[L]（高度受限于左壁）
  4. 因此 area(L, R') ≤ (R - L) × h[L] = area(L, R)

所以左壁 L 的最优搭档就是当前 R（宽度最大时）。L 已经不可能贡献更大的面积了，可以安全地 l++ 淘汰它。

与 Two Sum 的对比：
- Two Sum：移动规则由与 target 比较驱动（sum < target → l++）
- 盛水容器：移动规则由高度贪心驱动（谁矮淘汰谁）
- 共同点：都能严格证明移动是安全的，不会错过最优解

6. 模式二：读写指针 — 原地修改数组

6.1 模板

// 读写指针通用模板（用于原地修改数组）
// slow: 下一个「已处理好的元素」应该放的位置
// fast: 当前正在扫描的元素
int slow = 0;
for (int fast = 0; fast < n; fast++) {
    if (/* nums[fast] 应该被保留 */) {
        nums[slow] = nums[fast];  // 搬到前面
        slow++;                     // 扩大「已处理」区域
    }
}
// 此时 slow 就是新数组的长度，[0, slow) 是处理结果

6.2 不变量分析

📐 读写指针的循环不变量

在每轮循环结束时：

  • [0, slow) 是已经处理好的元素，满足题目要求
  • [slow, fast] 是已被覆盖/可废弃的元素
  • [fast+1, n) 是尚未扫描的元素

当 fast 扫描完整个数组后，[0, slow) 就是最终答案。

读写指针的优雅之处在于：fast 负责探索，slow 负责建设。fast 每到一处，根据规则决定要不要把 fast 处的东西「搬运」到 slow 处。

7. 读写指针题 1：移动零

LeetCode 283. Move Zeroes（Hot 100）
给定 nums = [0,1,0,3,12]，将所有 0 移到末尾，同时保持非零元素的相对顺序。必须原地操作。 
// 思路：slow 指向「下一个非零元素应该放的位置」
//       fast 扫描所有元素，遇到非零就搬到 slow 处
int slow = 0;
for (int fast = 0; fast < n; fast++) {
    if (nums[fast] != 0) {
        swap(nums[slow], nums[fast]);  // 非零元素搬到前面
        slow++;
    }
}
// 循环结束后，[0, slow) 全是非零，[slow, n) 全是零
执行过程可视化（nums = [0,1,0,3,12]）：
fast=0: nums[0]=0 → 跳过，slow 仍为 0
fast=1: nums[1]=1 → swap(0,1) → [1,0,0,3,12], slow=1
fast=2: nums[2]=0 → 跳过
fast=3: nums[3]=3 → swap(1,3) → [1,3,0,0,12], slow=2
fast=4: nums[4]=12 → swap(2,4) → [1,3,12,0,0], slow=3
结束：[0,3) = [1,3,12] 非零，[3,5) = [0,0] 全是零 ✅

8. 读写指针题 2：删除有序数组中的重复项

LeetCode 26. Remove Duplicates from Sorted Array
给定有序数组，原地删除重复元素，返回新长度。 
// 思路：[0, slow) 存放不重复的元素
//       fast 扫描，遇到「不等于 nums[slow-1]」的数就保留
int slow = 0;
for (int fast = 0; fast < n; fast++) {
    if (slow == 0 || nums[fast] != nums[slow - 1]) {
        nums[slow] = nums[fast];
        slow++;
    }
}
return slow;
变体推广：如果允许每个元素最多出现两次（80. Remove Duplicates II），只需把判断条件改为 slow < 2 || nums[fast] != nums[slow-2]。读写指针的不变量论证可以自然地处理这类推广。

9. 易错点与调试技巧

相向指针常犯的错误

错误后果正确做法
while (l <= r)l==r 时单元素被当作一对（无意义）用 l < r
在 3Sum 中忘记内层去重结果包含重复三元组找到解后跳过所有相同的 l 和 r
盛水容器：移动高的而不是矮的可能错过最优解证明过「淘汰矮的」才安全
不小心同时移动两个指针跳过潜在答案每步只移动一个指针（除非找到答案）

读写指针常犯的错误

错误后果正确做法
用 nums[fast] != nums[fast-1] 判断当 fast 跳过元素后，fast-1 可能已被覆盖用 nums[fast] != nums[slow-1]
忘记 slow 初始值结果不正确分析「已处理区域」的初始大小
