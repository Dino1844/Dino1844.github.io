1. 为什么复杂度是算法面试的「通用语言」

考虑一个问题：最大子数组和（LeetCode 53. Maximum Subarray）。

给定整数数组 nums = [-2, 1, -3, 4, -1, 2, 1, -5, 4]，找出具有最大和的连续子数组，返回其最大和。
答案：6（子数组 [4, -1, 2, 1]）

假设 n = 10⁵。以下是三种思路：

思路方法时间复杂度n=10⁵ 时能过吗？
A枚举所有子数组起点、终点、求和O(n³)❌ 10¹⁵ 次运算，宇宙毁灭
B枚举起点，累加求和O(n²)❌ 10¹⁰ 次运算，约 100 秒
CKadane 算法（动态规划）O(n)✅ 10⁵ 次运算，瞬间
💡 核心洞察：算法面试的本质不是「能不能做出来」，而是「做出来的方案能不能在给定数据范围内跑通」。复杂度就是衡量这个的通用语言。面试官说「你能优化一下吗？」，翻译过来就是「你能降低复杂度阶级吗？」

2. 大 O 标记法：形式化定义与直觉

形式化定义

定义：T(n) = O(f(n)) 当且仅当存在正常数 C 和 n₀，使得对所有 n ≥ n₀，有 T(n) ≤ C·f(n)。

用人话翻译：大 O 描述的是增长趋势的上界。当输入规模 n 足够大时，运行时间的增长不超过 f(n) 的某个常数倍。

三个关键直觉

  1. 忽略常数因子：O(2n) = O(n)，O(100n²) = O(n²)。因为当 n 足够大时，常数的影响远小于增长阶。
  2. 只保留最高阶项：O(n² + n + log n) = O(n²)。因为 n² 的增长远快于其他项。
  3. 大 O 是上界：O(n) 的算法也是 O(n²) 的（但我们在面试中说「算法是 O(n) 的」，取最紧的上界）。

容易混淆的概念

符号含义类比
O (大O)上界（最多这么快）「我最多迟到 10 分钟」
Ω (大Omega)下界（至少这么快）「至少需要 5 分钟」
Θ (大Theta)紧确界（刚好这么快）「恰好 8 分钟」

面试中几乎只说大 O。我们说「这个算法是 O(n log n) 的」，通常隐含这就是 Θ(n log n)。

3. 常见复杂度阶级：从 O(1) 到 O(2ⁿ)

以下设 n = 10⁶，假设每秒 10⁸ 次运算：

复杂度典型算法n=10⁶ 运算次数运行时间
O(1)哈希表查找、数组下标访问1瞬时
O(log n)二分查找、平衡树操作~20瞬时
O(√n)质数判定（试除法）1,000瞬时
O(n)遍历数组、Kadane10⁶~0.01s
O(n log n)归并排序、堆排序~2×10⁷~0.2s
O(n²)冒泡排序、枚举数对10¹²~3 小时 ❌
O(2ⁿ)递归求斐波那契~10³⁰¹⁰³⁰宇宙热寂 ❌
O(n!)全排列枚举天文数字❌❌❌
🧠 记忆锚点：假设 n = 10⁶，只有 O(n log n) 及更低的复杂度才可接受。如果 n = 10³，O(n²) 也勉强可行。
关键公式：可接受运算次数 ≈ 10⁷ ~ 10⁸（1 秒的 C++ 循环次数）

对数复杂度精讲

O(log n) 可能是初学者最难直观理解的。它的本质是：每次操作将问题规模缩小为原来的一部分。

// 二分查找：每次将搜索范围减半
int lo = 0, hi = n - 1;
while (lo <= hi) {
    int mid = lo + (hi - lo) / 2;  // 防溢出写法
    if (nums[mid] == target) return mid;
    else if (nums[mid] < target) lo = mid + 1;
    else hi = mid - 1;
}

反转视角：log₂(n) 就是「n 可以连续除以 2 多少次」。log₂(10⁶) ≈ 20，所以二分查找最多 20 步就能从 100 万个数中找到目标。

4. 如何分析一段代码的复杂度：四步法

步骤 1：确定变量

谁是 n？可能是数组长度、链表长度、树的节点数、字符串长度等。如果输入有多个维度（如矩阵 m×n），复杂度可能包含多个变量。

步骤 2：找最内层操作

找到执行次数最多的那段代码（通常是嵌套最深的循环体）。

步骤 3：分析该操作的执行次数（用 n 表示）

// 例 1：O(n)
for (int i = 0; i < n; i++) sum += nums[i];  // 循环体执行 n 次

// 例 2：O(n²)
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)
        cnt++;  // 循环体执行 n² 次

// 例 3：O(n²) 中的 O(n²) —— 很多人会错！
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)
        cnt++;  // 执行 n(n-1)/2 次，仍是 O(n²)

// 例 4：O(n log n)
for (int i = 0; i < n; i++) {          // 外循环 n 次
    int x = i;
    while (x > 0) { x /= 2; cnt++; }  // 内循环 log(i) 次 → 总共 O(n log n)
}

步骤 4：忽略常数和低阶项

// 这段代码的复杂度？
for (int i = 0; i < n; i++) sum += nums[i];            // O(n)
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++) cnt++;                  // O(n²)
// 总复杂度：O(n) + O(n²) = O(n²)

递归的复杂度：主定理（Master Theorem）速查

对于形如 T(n) = a·T(n/b) + f(n) 的递归：

条件复杂度例子
f(n) = O(nlog_b a - ε)T(n) = Θ(nlog_b a)—
f(n) = Θ(nlog_b a)T(n) = Θ(nlog_b a · log n)归并排序: a=2,b=2,f(n)=n → O(n log n)
f(n) = Ω(nlog_b a + ε)T(n) = Θ(f(n))—
面试中最常用的结论：归并排序/快速排序 = O(n log n)；二叉树遍历 = O(n)（每个节点访问一次）；回溯 = O(k·分支数^深度)，通常指数级。

5. 从数据范围反推所需复杂度

这是面试中最实用的技能。看到题目给出数据范围，你应该立刻知道需要什么复杂度的算法：

数据范围 n可接受的最坏复杂度常见算法
n ≤ 10O(n!), O(2ⁿ)全排列、暴力回溯
n ≤ 20O(2ⁿ)状态压缩 DP、子集枚举
n ≤ 100O(n³)Floyd-Warshall、区间 DP
n ≤ 10³O(n²)枚举数对、简单 DP
n ≤ 10⁵O(n log n)排序、堆、二分查找、大多数 Hot 100
n ≤ 10⁶O(n)线性扫描、计数排序、Kadane
n ≤ 10⁹O(log n) 或 O(1)二分查找、数学公式
🎯 LeetCode 题目特征：Hot 100 中绝大多数题目的数据范围是 n ≤ 10⁵，这意味着你的算法必须是 O(n log n) 或更优。如果你写出了一个 O(n²) 的算法，大概率会 TLE（超时）。

面试中你不需要从头实现数据结构。STL 是你的武器库，但你必须知道每件武器的复杂度代价。

6.5 必备的技巧写法

// 2. 原地构造（避免临时对象）
v.emplace_back(x, y);  // 优于 v.push_back({x, y})

// 3. 结构绑定遍历（C++17）
for (auto& [key, val] : mp) { ... }

// 4. 自定义排序
sort(v.begin(), v.end(), [](int a, int b) { return a > b; });

// 5. lambda 捕获（DFS/回溯必备）
auto dfs = [&](int u, int parent) -> void {
    for (int v : adj[u]) {
        if (v != parent) dfs(v, u);
    }
};

7. 真题演练：复杂度分析实战

题目 1：最大子数组和（LeetCode 53）

题眼：n ≤ 10⁵，必须 O(n log n) 以内

// 解法 A：暴力枚举（O(n³)）—— TLE
int ans = INT_MIN;
for (int i = 0; i < n; i++)
    for (int j = i; j < n; j++) {
        int sum = 0;
        for (int k = i; k <= j; k++) sum += nums[k];
        ans = max(ans, sum);
    }

// 解法 B：前缀和优化（O(n²)）—— 仍然 TLE
vector<int> pre(n + 1, 0);
for (int i = 0; i < n; i++) pre[i+1] = pre[i] + nums[i];
int ans = INT_MIN;
for (int i = 0; i < n; i++)
    for (int j = i; j < n; j++)
        ans = max(ans, pre[j+1] - pre[i]);

// 解法 C：Kadane 算法（O(n)）—— ✅ AC
int cur = 0, ans = INT_MIN;
for (int x : nums) {
    cur = max(cur + x, x);  // 要么扩展，要么从头开始
    ans = max(ans, cur);
}
复杂度分析：Kadane 算法 O(n) 时间、O(1) 空间。为什么对？不变量：cur 始终是「以当前位置结尾」的最大子数组和。递推：以 i 结尾的最大子数组，要么是以 i-1 结尾的最大子数组 + nums[i]，要么是 nums[i] 单独成段。

题目 2：Two Sum（LeetCode 1）

题眼：n ≤ 10⁴，O(n²) 勉强可过但 O(n) 才是面试标准

// 解法 A：暴力 O(n²)，空间 O(1)
for (int i = 0; i < n; i++)
    for (int j = i+1; j < n; j++)
        if (nums[i] + nums[j] == target) return {i, j};

// 解法 B：排序 + 双指针 O(n log n)，空间 O(n)（存原下标）
// 适用场景：返回的是值而非下标

// 解法 C：哈希表 O(n)，空间 O(n)——面试最优解
unordered_map<int, int> mp;
for (int i = 0; i < n; i++) {
    if (mp.count(target - nums[i])) return {mp[target - nums[i]], i};
    mp[nums[i]] = i;
}
解法时间空间n=10⁴评价
暴力O(n²)O(1)10⁸ ≈ 1s会过但面试不过
排序+双指针O(n log n)O(n)~1.3×10⁵可行，但需证明下标正确
哈希表O(n)O(n)10⁴最优，经典空间换时间

题目 3：斐波那契数列（LeetCode 509）

题眼：同一个问题，不同实现方式有截然不同的复杂度

// 实现 A：朴素递归 O(2ⁿ)——n=40 就卡死
int fib(int n) {
    if (n <= 1) return n;
    return fib(n-1) + fib(n-2);
}
// T(n) = T(n-1) + T(n-2) + O(1) → T(n) = O(φⁿ) ≈ O(1.618ⁿ)

// 实现 B：记忆化搜索 O(n)——正确利用空间
int memo[31]; // memset to -1
int fib(int n) {
    if (n <= 1) return n;
    if (memo[n] != -1) return memo[n];
    return memo[n] = fib(n-1) + fib(n-2);
}

// 实现 C：自底向上 DP O(n)，空间 O(1)
int fib(int n) {
    if (n <= 1) return n;
    int a = 0, b = 1;
    for (int i = 2; i <= n; i++) {
        int c = a + b; a = b; b = c;
    }
    return b;
}
复杂度跃迁：O(φⁿ) → O(n) → O(n) 但空间 O(1)。同一个数学问题的三种实现跨越了可解与不可解的鸿沟。这就是复杂度分析的意义。

题目 4：二分查找的三种写法（边界分析）

二分查找看似简单，但边界写错就会死循环或漏元素。三种标准写法覆盖所有场景：

// 写法 1：查找 target（闭区间）——最常用
int lo = 0, hi = n - 1;
while (lo <= hi) {
    int mid = lo + (hi - lo) / 2;
    if (nums[mid] == target) return mid;
    else if (nums[mid] < target) lo = mid + 1;
    else hi = mid - 1;
}

// 写法 2：查找第一个 ≥ target 的位置（lower_bound）
int lo = 0, hi = n;  // 左闭右开
while (lo < hi) {
    int mid = lo + (hi - lo) / 2;
    if (nums[mid] < target) lo = mid + 1;
    else hi = mid;
}

// 写法 3：查找第一个 > target 的位置（upper_bound）
int lo = 0, hi = n;
while (lo < hi) {
    int mid = lo + (hi - lo) / 2;
    if (nums[mid] <= target) lo = mid + 1;
    else hi = mid;
}
⚠️ 最容易犯的错误：
1. mid = (lo + hi) / 2 —— lo+hi 可能溢出！用 lo + (hi - lo) / 2
2. 闭区间写 while (lo < hi) —— 会漏掉单元素情况
3. 循环内忘了 +1 或 -1 —— 导致死循环
