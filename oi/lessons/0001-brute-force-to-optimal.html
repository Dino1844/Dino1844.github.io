1. 所有算法优化的本质：缩小搜索空间

想象你在一本 100 万字的书中找一个词。你有两种方法：

  • 方法 A：从头到尾逐页翻（O(n)，笨但有效）
  • 方法 B：翻到字典的索引页，按字母顺序定位（O(1)，聪明但需要额外的索引结构）

这两种方法代表了算法面试中最核心的五种优化策略：

#策略核心思想本课例题
1空间换时间用额外存储让查找从 O(n) 变 O(1)Two Sum
2单调性剪枝利用单调性质证明某些分支不必探索Container With Most Water
3预计算 / 缓存把反复计算的值提前算好存下来Trapping Rain Water
4排序创造结构付出 O(n log n) 排序，换取 O(n) 解决3Sum
5问题分解把大问题拆成子问题（DP/分治）（Lesson 0016）
🧠 面试思维框架：每次你写出一个暴力算法后，问自己三个问题：
1. 瓶颈在哪？（哪步操作最慢？什么操作被重复执行最多？）
2. 有冗余吗？（有没有信息被重复计算？有没有搜索分支其实不需要探索？）
3. 能给输入加结构吗？（排序？哈希表？前缀和？树？堆？）

2. 策略一：空间换时间 — Two Sum

2.1 问题回顾

给定 nums = [2,7,11,15], target = 9，找出和为 target 的两个数的下标。

2.2 暴力解法（O(n²)）

// 搜索空间：所有数对 (i, j)，共 C(n,2) = n(n-1)/2 个候选
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)
        if (nums[i] + nums[j] == target) return {i, j};

瓶颈分析：对于每个 nums[i]，我们需要找到 target - nums[i]。内层循环用 O(n) 时间做这个查找。

2.3 优化：用哈希表把查找变成 O(1)

// 关键洞察：用「存储」替代「搜索」
// 之前：对每个 i，我们 O(n) 搜索 target-nums[i]
// 之后：对每个 i，我们 O(1) 查询 target-nums[i] 是否在哈希表中

unordered_map<int, int> mp;  // value → index
for (int i = 0; i < n; i++) {
    int need = target - nums[i];
    if (mp.count(need)) return {mp[need], i};
    mp[nums[i]] = i;
}

策略 1：空间换时间

何时适用：当瓶颈是「查找某个值是否存在/位置」时。

代价：O(n) 的空间。

收益：查找从 O(n) 降为 O(1)，总时间从 O(n²) 降为 O(n)。

一句话：用内存记录见过的信息，避免回头重新看。

2.4 这个策略还能解的题

  • 两数之和变体：Two Sum IV（BST 中两数之和）— 同样的哈希表思路
  • 最长连续序列（128）：用 unordered_set 存所有数，再用 O(1) 检查连续性
  • 复制带随机指针的链表（138）：用哈希表建立原节点→新节点的映射

3. 策略二：利用单调性剪枝 — Container With Most Water

3.1 问题

LeetCode 11. Container With Most Water
给定 height = [1,8,6,2,5,4,8,3,7]，选择两条线作为容器壁，使得容器能容纳最多的水。
面积 = 两条线的距离 × min(左边高度, 右边高度)

3.2 暴力解法（O(n²)）

// 搜索空间：所有线对 (i, j)
int ans = 0;
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)
        ans = max(ans, (j - i) * min(height[i], height[j]));
瓶颈分析：搜索空间是 C(n,2) = O(n²) 个数对。但真的每个数对都需要检查吗？

3.3 关键洞察：单调性论证

设左指针 L = 0，右指针 R = n-1。当前面积 = (R-L) × min(h[L], h[R])。

关键问题：移动哪一根？

假设 h[L] < h[R]（左边更矮）。如果固定 L 不动，把 R 往左移：

  • 宽度 (R-L) 必然减小
  • min(h[L], h[R]) ≤ h[L]（因为左边更矮，min 受限于左边）
  • 所以 面积不可能超过当前

因此，以 L 为左壁的所有其他容器的面积都不会超过当前 (L, R)。所以我们可以安全地放弃 L，把它右移。同理，如果 h[R] < h[L]，就把 R 左移。

正确性证明（不变量论证）：
每一步我们都在「淘汰」一根柱子。需要证明我们不会因为淘汰它而错过最优解。
当 h[L] ≤ h[R] 时，以 L 为左壁的最优搭档就是当前 R（因为宽度最大，且高度受限于 h[L]）。所以 L 已经贡献了它能产生的最大面积，安全淘汰。

3.4 最优解（O(n)）

int l = 0, r = n - 1, ans = 0;
while (l < r) {
    ans = max(ans, (r - l) * min(height[l], height[r]));
    if (height[l] < height[r]) l++;  // 淘汰矮的
    else r--;
}

策略 2：单调性剪枝

何时适用：当你能证明某个搜索分支不可能产生比当前更好的答案时，就可以安全剪掉它。

核心思维：不是「枚举所有可能然后挑最好的」，而是「证明某些候选不可能更好，直接排除」。

收益：搜索空间从 O(n²) 降为 O(n)。

一句话：利用问题的单调性质，证明大部分候选不可能是答案。

3.5 这个策略还能解的题

  • 三数之和（15）：排序后固定一端，内层双指针根据和的符号移动
  • 接雨水（42）双指针解法：维护左右最大高度，谁矮移动谁
  • 有序数组的 Two Sum（167）：经典对撞指针

4. 策略三：预计算消除重复 — Trapping Rain Water

4.1 问题

LeetCode 42. Trapping Rain Water
给定 height = [0,1,0,2,1,0,1,3,2,1,2,1]，计算下雨后能接多少水。
每个位置 i 的蓄水量 = min(左边最高, 右边最高) - height[i]（如果为正）

4.2 暴力解法（O(n²)）

// 对每个位置 i，分别向左/右扫描找最大高度
int ans = 0;
for (int i = 0; i < n; i++) {
    int lmax = 0, rmax = 0;
    for (int j = 0; j <= i; j++) lmax = max(lmax, height[j]);
    for (int j = i; j < n; j++) rmax = max(rmax, height[j]);
    ans += max(0, min(lmax, rmax) - height[i]);
}
瓶颈分析：每个位置 i 都重复扫描了整个数组来找左最大和右最大。同一个前缀的最大值被算了 n 次！

4.3 关键洞察：预计算

「i 位置左边的最大高度」是前缀信息，可以一次性从左到右算出来。「i 位置右边的最大高度」是后缀信息，可以一次性从右到左算出来。这两个数组就是我们对原问题的预计算。

// 预计算 leftMax[i] = max(height[0..i])
vector<int> leftMax(n);
leftMax[0] = height[0];
for (int i = 1; i < n; i++)
    leftMax[i] = max(leftMax[i-1], height[i]);

// 预计算 rightMax[i] = max(height[i..n-1])
vector<int> rightMax(n);
rightMax[n-1] = height[n-1];
for (int i = n-2; i >= 0; i--)
    rightMax[i] = max(rightMax[i+1], height[i]);

// O(n) 计算答案
int ans = 0;
for (int i = 0; i < n; i++)
    ans += max(0, min(leftMax[i], rightMax[i]) - height[i]);

时间复杂度：O(n) 空间复杂度：O(n)（两个辅助数组）

4.4 进一步优化：双指针做到 O(1) 空间

注意到：对于位置 i，我们只关心 min(leftMax[i], rightMax[i])。如果我们用双指针从两端向中间移动，只维护当前的 leftMax 和 rightMax，可以去掉辅助数组：

int l = 0, r = n - 1;
int lmax = 0, rmax = 0, ans = 0;
while (l < r) {
    lmax = max(lmax, height[l]);
    rmax = max(rmax, height[r]);
    if (lmax < rmax) {
        ans += lmax - height[l];  // leftMax 固定了右边界的瓶颈
        l++;
    } else {
        ans += rmax - height[r];
        r--;
    }
}
这题展示了三级优化阶梯：
O(n²) 暴力（重复扫描）→ O(n)/O(n) 预计算（缓存前缀）→ O(n)/O(1) 双指针（用单调性代替存储）
面试中把这三步全部展示出来，就是一道 Hard 题的完美表现。

策略 3：预计算 / 缓存

何时适用：当暴力解中存在「对同一信息的重复计算」时。特征是：你能写出某个量（前缀/后缀/子结构）的递推公式。

常见形式：前缀和、前缀最大值、后缀最大值、前缀异或、前缀出现次数。

一句话：一次性提前算好所有中间结果，需要时 O(1) 取用。

5. 策略四：排序创造结构 — 3Sum

5.1 问题

LeetCode 15. 3Sum
给定 nums = [-1,0,1,2,-1,-4]，找出所有和为 0 的不重复三元组。
答案：[[-1,-1,2], [-1,0,1]]

5.2 暴力解法（O(n³)）

// 搜索空间：所有三元组 (i, j, k)，C(n,3) ≈ n³/6
for (int i = 0; i < n; i++)
    for (int j = i+1; j < n; j++)
        for (int k = j+1; k < n; k++)
            if (nums[i] + nums[j] + nums[k] == 0)
                // 记录 + 去重（烦！）

瓶颈分析：三元组搜索 + 去重。如果把数组排序，就能同时解决两个问题：1) 用双指针把内两层循环从 O(n²) 降到 O(n)；2) 去重变得简单（相等的数相邻）。

5.3 排序 + 固定一端 + 双指针

// 核心思路：排序后固定 i，问题变成在 (i+1, n-1) 中找两数之和 = -nums[i]
sort(nums.begin(), nums.end());
vector<vector<int>> ans;

for (int i = 0; i < n - 2; i++) {
    // 去重 1：跳过相同的第一个数
    if (i > 0 && nums[i] == nums[i-1]) continue;

    int l = i + 1, r = n - 1;
    while (l < r) {
        int sum = nums[i] + nums[l] + nums[r];
        if (sum == 0) {
            ans.push_back({nums[i], nums[l], nums[r]});
            // 去重 2：跳过相同的第二、三个数
            while (l < r && nums[l] == nums[l+1]) l++;
            while (l < r && nums[r] == nums[r-1]) r--;
            l++; r--;
        } else if (sum < 0) {
            l++;  // 和太小，需要更大的数
        } else {
            r--;  // 和太大，需要更小的数
        }
    }
}

时间复杂度：排序 O(n log n) + 外循环 O(n) × 双指针 O(n) = O(n²) 空间：O(1)（不计输出）

为什么排序后去重变得简单？
排序后相等的元素相邻。如果 nums[i] == nums[i-1]，说明以 nums[i] 开头的所有三元组已经在处理 nums[i-1] 时全部找到了。跳过即可避免重复。这个「排序→去重」的模式在回溯中也极其常用。

策略 4：排序创造结构

何时适用：当原始数组无序，但有序后可以利用单调性、二分查找或双指针加速时。

代价：O(n log n) 的排序。

收益：后续操作获得 O(n) 或 O(log n) 的效率。

一句话：花 O(n log n) 给数据「塑形」，然后用 O(n) 解决核心问题。

5.4 这个策略还能解的题

  • 四数之和（18）：排序 + 固定两端 + 中间双指针，O(n³)
  • 最接近的三数之和（16）：同 3Sum 框架，追踪最接近 target 的和
  • 合并区间（56）：按起点排序后，合并变得简单

6. 四大策略总结 + 面试速查表

策略核心操作典型复杂度收益关键特征
① 空间换时间建哈希表O(n²)→O(n)，空间 O(1)→O(n)瓶颈是「查找」
② 单调性剪枝双指针/贪心移动O(n²)→O(n)能证明某些分支不必探索
③ 预计算缓存前缀/后缀数组，DP 表O(n²)→O(n)对同一信息重复计算
④ 排序创造结构排序 + 双指针/二分O(n²)→O(n log n)排序后能利用单调性/二分

0s-10s：复述题目，确认输入/输出/边界
10s-20s：说出暴力解 + 复杂度（建立基线）

40s-60s：匹配策略：查找慢？→ 哈希表。有序后能优化？→ 排序。有冗余计算？→ 预计算。有单调性？→ 双指针剪枝。
