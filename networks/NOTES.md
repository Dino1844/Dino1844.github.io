# Notes

## 学习设计偏好

用户明确偏好一种 **「问题主界面 + 知识框架」** 的架构：

- **主界面**：以一个核心问题（如「浏览器输入 URL 后发生了什么」）作为入口。这个问题本身就是一张网络知识的地图。
- **概念索引**：从主问题中拆分出子问题和概念节点，每个节点链接到更深层的知识。
- **知识框架**：深层知识不是孤立的 reference 条目，而是一个**互联的思维框架**——层与层之间的设计动机、协议之间的配合与 trade-off、问题排查的心智模型。

这意味着：
- `index.html` 应该是那个主界面——一个交互式的概念地图
- `lessons/` 是逐个击破的专题深潜
- `reference/` 应该是互联的思维框架，而非孤立 cheat sheet
- 每个 lesson 都应该能从主界面通过概念路径抵达

## 语言偏好
- 教学语言：中文
- 关键术语：保留英文原词（如 TCP, DNS, HTTP），首次出现时给出中文对照

## 课程风格
- 不要死记硬背的八股文，要解释「为什么这样设计」
- 适当使用类比，但要标注类比的局限性
- 每个 lesson 结束后给一个可验证的小练习
