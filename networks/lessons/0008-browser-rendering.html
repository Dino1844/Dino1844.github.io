第 8 课：浏览器渲染 —— 从 HTML 到像素

计算机网络 · ← 概念地图 · 约 15 分钟 · 术语表

URL 之旅的最后一站：HTTP 响应已经把 HTML 送到了浏览器，接下来怎么把它变成屏幕上的像素？这不是严格意义上的"网络"知识，但它完成了整个 URL 之旅的最后闭环。

🎯 本课目标：理解浏览器的关键渲染路径——HTML→DOM、CSS→CSSOM、布局、绘制、合成。以及"为什么 JavaScript 会阻塞渲染"。

1. 渲染流水线：五个阶段

HTML 解析
→ DOM 树 → CSS 解析
→ CSSOM 树 → 布局 Layout
计算位置大小 → 绘制 Paint
生成像素指令 → 合成 Composite
分层合并显示

Phase 1: HTML → DOM

浏览器拿到 HTML 字节流 → 解码为字符 → 词法分析为 Token → 构建 DOM 树。DOM 树是页面结构的对象表示——每个标签是一个节点，嵌套关系是父子关系。

关键行为：HTML 解析遇到 <script> 会暂停，等脚本下载并执行完再继续。因为脚本可能调用 document.write() 改变后续 HTML。所以 <script> 放 </body> 前或加 async/defer 是重要的性能优化。

Phase 2: CSS → CSSOM

CSS 被解析为 CSSOM（CSS Object Model）树。与 DOM 不同，CSS 的解析是层叠的——浏览器需要计算每个元素的最终样式（考虑继承、层叠、优先级）。

CSS 不阻塞 DOM 构建，但阻塞渲染。因为 CSSOM + DOM = Render Tree（渲染树），两个都完成了才能进入下一阶段。

Phase 3: 布局（Layout / Reflow）

浏览器遍历 Render Tree，计算每个可见元素的精确位置和大小。这个过程是流式的——一个元素的位置影响后续所有元素。

改变 width/height/position 等几何属性会触发回流（Reflow）——整个布局重新计算，开销很大。

Phase 4: 绘制（Paint）

把每个元素的视觉样式（颜色、阴影、边框等）转换为像素绘制指令，填入不同的图层（Layer）。改变 color/background 等非几何属性只需要重绘（Repaint），不触发回流。

Phase 5: 合成（Composite）

浏览器把多个图层按顺序叠加，生成最终的屏幕像素。GPU 在这一步大显身手——transform 和 opacity 的动画只影响合成层，完全不触发回流或重绘，可以跑满 60fps。

2. 回流 vs 重绘 vs 合成 —— 性能代价天差地别

触发属性（举例）触发什么代价优化建议
width, height, left, top, margin, padding ...回流 Layout → Paint → Composite高用 transform: scale/translate 代替
color, background, box-shadow ...重绘 Paint → Composite中尽量合批修改
transform, opacity仅合成 Composite低动画首选方案
💡 关键优化原则：CSS 动画如果只改 transform 和 opacity，浏览器把它放在独立的合成层中，由 GPU 处理——主线程完全不受影响，即使 JavaScript 在跑长任务也不会卡动画。

3. 从输入 URL 到第一帧显示：完整回顾

把这 8 课串起来——你现在能完整解释整个过程了：

  1. DNS（第 2 课）：把 example.com 翻译成 IP
  2. TCP（第 3 课）：三次握手建立可靠连接
  3. TLS（第 7 课）：握手协商加密密钥，验证证书
  4. HTTP（第 6 课）：发送 GET 请求，收到 200 OK + HTML
  5. IP（第 4 课）：每一跳查路由表，MAC 逐跳变，IP 端到端不变
  6. 链路层（第 5 课）：交换机按 MAC 转发帧，ARP 翻译 IP→MAC
  7. 渲染（本课）：HTML→DOM→CSSOM→Layout→Paint→Composite

从你敲下回车到页面出现，通常只需要 1–3 秒。这背后是几十次网络往返、数千行协议代码、全球数百台路由器的协作。你现在理解了这每一步。
