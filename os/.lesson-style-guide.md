## 深度要求（核心）

### 概念更本质
不停留在"这个机制怎么做"，讲透"为什么这个设计是对的"。每个关键机制要给以下层面的解释：
- **动机层**：它解决什么问题？
- **机制层**：它怎么工作？（可追踪的代码路径或硬件交互步骤）
- **必然性层**：为什么这个解法是必然的/最优的？（能不能换一个设计？换了会怎样？）
- **代价层**：它付出了什么代价？（性能？复杂度？安全性？）

### 联系更广
每课至少 2 处回接旧课、2 处预告后课。把课程织成网，不是孤立知识点。

### 上下文衔接
旧概念在新语境复现——如 0003 回接 0001 的间接层范式、0004 回接 0002 的上下文切换代价（TLB 刷新）、0009 把全部概念汇聚到一次系统调用追踪。

### 思考深度
每个机制要讲清"为什么必然如此"，不只给结论。例如：TLB 为什么可以很小但有极高命中率？（空间局部性）多级页表为何是四级而非三级或五级？（48 位地址 ÷ 9 位/级 = 5+ 级，四级加 9+12+9+9+9=48）

### 设计范式提炼
这是最关键的。OS 中很多设计共事同一种模式（间接、缓存、惰性求值、批处理、机制策略分离、HW-SW 协同）。**要把这些"元范式"显式提炼成 `.meta-box` 块**，标注"范式 #N"，说明"这一招为什么管用、还在 OS 的哪里出现"。让学生看到"同一招贯穿全书"，而不是每课学一个新机制。

### OS 课程的"推导"：代码路径追踪
ML 课程的 `.derivation` 块是数学推导（一步步代数变换），OS 课程对应的是**机制推演**——追踪一次系统调用或硬件交互的完整路径：
```
用户态 read(fd, buf, size)
→ libc 包装（syscall 指令）
→ 陷入内核（trap frame 保存用户态寄存器）
→ sys_read() → 从 fd 查到 file → 查到 inode
→ 文件系统层（检查 buffer cache → 未命中 → 读块设备）
→ 块层（I/O 调度 → 合并相邻请求）
→ 驱动（编程 DMA 控制器 → 发起 I/O）
→ 设备中断 → 内核态（handle IRQ → 唤醒等待进程）
→ 返回用户态
```
每一步标注"为什么这样走"——这是操作系统理解的"推导深度"。

## 推导/追踪题（.problem 块）
- 4–6 题左右，难度递增：L1 基础 / L2 理解 / L3 进阶。
- 用 `.plevel.l1`/`.l2`/`.l3` 标签。
- 每题：题目 → 可折叠 `<details>` 提示 → 可折叠 `<details>` 完整解答 `.sol`。
- **考真机制追踪或设计推理**——不是"查上下文能答的选择题"。
- L3 题应该是"把本课范式用到新场景"或"设计一个替代机制并分析代价"。
- 至少 1 题 L3 是触类旁通——训练迁移能力。

## 引用约定（hub-and-spoke）
0001 是**全书基石（hub）**，不是线性链第一环。它建立 6 个公理/对象，后续课展开。
- **真回接**（本课用到 0001 建立的某对象：间接层、机制/策略分离……）→ 用 **"基石 0001 §X"** 标记。
- **空回接**（0001 只是预告、本课才是定义处）→ 改成"本课展开 0001 §X 预告的…"
- footer：**"上一课"** 只指直接前驱，**"回接"** 指跨课复现，**"基石"** 指 hub 0001。三者不混用。
- 叙述性提及（范式表、闭环总结、习题指引里自然提到 0001）可不加标记，但不得用"上一课 0001"这种把 hub 伪装成前驱的措辞。

## 引用约定（cite-as-you-teach）
不挂"OSTEP 第 X 章说…"标签。把 OSTEP、xv6、Linux 源码的信息融进叙事。出处只在 `.primary-source` 列出。
示例（好）："xv6 的 `scheduler()` 函数这样选择下一个进程：它遍历进程表，找到第一个 `RUNNABLE` 的进程然后切换。这个算法就是最简单的 FIFO——公平但响应时间糟糕。"
