第 1 课：URL 之旅全览

计算机网络 · ← 返回概念地图 · 约 15 分钟

你每天在浏览器里输入网址几十次。按下回车的瞬间，你的计算机开始了一场横跨全球的接力赛——从你的键盘，经过操作系统、网卡、路由器、海底光缆，到达万里之外的服务器，再原路返回。这一切，在几百毫秒内完成。

本课将带你走完这趟旅程的每一个阶段。不需要记住所有细节——你只需要建立一个全局心智模型。后续每一课会逐一深入每个阶段。

🎯 本课目标：学完后，你应该能画出从「输入 URL」到「页面显示」的完整流程图，并说出每一阶段的核心目的。

🗺️ 旅程地图：七个阶段

Phase 1 · 应用层
DNS 解析 —— 把域名翻译成 IP 地址
计算机不认识 example.com，它只认识 IP 地址如 93.184.216.34。DNS（Domain Name System）就是互联网的电话簿。浏览器先查本地缓存，没有就问操作系统，操作系统问路由器，路由器问 ISP 的 DNS 服务器……层层向上直到找到答案。整个过程是分级查询：根域名服务器 → 顶级域名服务器（.com）→ 权威域名服务器。
Phase 2 · 传输层
TCP 三次握手 —— 建立可靠连接
拿到 IP 后，浏览器通过 TCP（传输控制协议）与服务器建立连接。TCP 的核心承诺是：数据不丢、不乱、不重复。三次握手就是双方互相确认收发能力的过程：
① 客户端 → 服务器：SYN（嘿，能听到吗？）
② 服务器 → 客户端：SYN-ACK（听到了，你能听到我吗？）
③ 客户端 → 服务器：ACK（能听到，开始传数据吧）
Phase 3 · 传输/应用之间
TLS 握手 —— 建立加密信道（HTTPS）
如果网址是 https://（现在 90%+ 的网站都是），TCP 连接建立后会立即进行 TLS 握手。双方协商加密算法、验证服务器证书（「你真的是 example.com 吗？」），然后生成只有双方知道的对称密钥。此后所有 HTTP 数据都在这个加密信道中传输，中间人只能看到乱码。
Phase 4 · 应用层
HTTP 请求-响应 —— 获取资源
安全信道建立后，浏览器发送 HTTP 请求：
GET /index.html HTTP/1.1
Host: example.com
服务器收到后返回响应：HTTP/1.1 200 OK，附上 HTML 内容。一个页面通常包含几十个资源（CSS、JS、图片），浏览器会并行发起多个请求。
Phase 5 · 网络层
IP 路由 —— 数据在网络中逐跳转发
HTTP 消息被 TCP 切成数据段，数据段被 IP 层打包成数据包。每个路由器查路由表，把包转发到「离目的地更近」的下一跳。这就像快递经过多个中转站，每个中转站只看下一站的地址，不关心全貌。IP 层不保证可靠性——包可能丢失、乱序、重复，这些由 TCP 来兜底。
Phase 6 · 链路层
链路层 —— 同一网段内的帧传输
IP 包需要被封装成帧才能在物理链路上传输。链路层用 MAC 地址标识同一网络内的设备。ARP 协议负责把 IP 地址翻译成 MAC 地址（「192.168.1.1 的 MAC 地址是多少？」）。交换机根据 MAC 地址转发帧，最终通过网线、光纤或 WiFi 信号到达下一跳路由器。
Phase 7 · 客户端
浏览器渲染 —— 从 HTML 到像素
浏览器收到 HTML 后，开始解析、构建 DOM 树和 CSSOM 树，计算布局（每个元素的位置和大小），然后绘制（Paint）成像素，最后通过 GPU 合成（Composite）显示在屏幕上。这个过程可能触发新的网络请求（图片、字体、API 调用），循环继续。

🧅 核心心智模型：分层

这七步可以映射到网络设计的核心思想——分层。每一层只关心自己的职责，向上层提供服务，向下层委托细节：

层 协议/技术 核心问题 身份标识
应用层HTTP, DNS, TLS数据是什么含义？域名 / URL
传输层TCP, UDP数据如何可靠/高效地到达？端口号
网络层IP, BGP, OSPF数据如何跨越多个网络？IP 地址
链路层Ethernet, WiFi, ARP数据如何在同一个网络内传输？MAC 地址
物理层网线、光纤、无线电比特如何在物理介质上传输？—

分层的关键洞见：当你写一个浏览器时，你只需要关心 HTTP，不用管底层是 WiFi 还是光纤。这就是分层的力量——每一层可以独立演进，只要接口不变。

💡 一个强大的思维技巧：当你遇到网络问题时，逐层排查。ping 不通？先查 IP 层。能 ping 通但网页打不开？查传输层（端口是否开放）和应用层（HTTP 状态码）。这就是逐层排查方法论，后续会专门有一课讲这个。
