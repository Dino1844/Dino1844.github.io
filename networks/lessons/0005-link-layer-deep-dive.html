第 5 课：链路层 —— 同一网络内的帧传输

传输层   TCP · UDP
网络层   IP · BGP

把数据包从北京送到旧金山，跨越无数路由器——那是网络层（IP）的工作。但在每一跳之间，数据包需要真正地在某根线缆、某段光纤、某个 WiFi 信道上传输。谁来做这件事？链路层。

🎯 本课目标：理解链路层解决了什么问题、MAC 地址与 IP 地址的分工、ARP 的工作原理、交换机的自学习机制、以及以太网帧的结构。学完后你应该能解释「同一个局域网内，两台电脑怎么找到对方并可靠地交换数据」。

1. 链路层要解决什么问题？

网络层的 IP 协议只管「这条包最终要送到 IP 地址 X」——但它在每跳之间不管具体的传输细节。链路层的职责是：

  • 在同一段物理链路上（同一根网线、同一个 WiFi 信道），把数据从一个设备传到相邻设备
  • 识别这段链路上的邻居——用的是 MAC 地址，不是 IP 地址
  • 处理这段链路特有的问题：冲突怎么避免？信号错误怎么检测？

关键洞察：链路层是跳与跳之间的协议，网络层是端到端之间的协议。一个 IP 包从北京到旧金山，链路层的帧在每一跳都被拆掉重新封装——源 MAC 和目的 MAC 每一跳都在变，但源 IP 和目的 IP 始终不变。

🔑 核心比喻：IP 地址是「收件人地址」（终点），MAC 地址是「当前这一站的交接人」（每一跳）。快递从北京发往上海，收件地址不变，但北京分拣中心交给卡车司机、卡车司机交给上海分拣中心——每一次交接，交接人都不一样。

2. MAC 地址 —— 设备的「身份证」

MAC（Media Access Control）地址是一个 48 位（6 字节）的硬件地址，通常写作 00:1A:2B:3C:4D:5E。

几个关键事实：

  • 烧录在网卡中——每块网卡出厂时由制造商分配一个全球唯一的 MAC 地址。前 24 位是制造商的 OUI（组织唯一标识符），后 24 位由制造商自分配
  • 扁平结构——IP 地址是分层的（192.168.x.x 属于某个子网），MAC 地址是扁平的（没有任何子网概念，在哪都一样）
  • 只在局域网内有效——MAC 地址出了当前广播域就没用了，路由器不会把 MAC 地址转发到另一个网络

3. ARP —— 「192.168.1.5 的 MAC 地址是多少？」

现在有了一个核心矛盾：你的电脑知道目的 IP（比如 192.168.1.5），但要在这个局域网里真正把帧发过去，必须知道对方的 MAC 地址。ARP（Address Resolution Protocol）就是解决这个问题的。

ARP 的工作过程

  1. 主机 A 想和 192.168.1.5 通信，但不知道它的 MAC 地址
  2. A 在局域网内广播一个 ARP 请求：「192.168.1.5 是谁？告诉 192.168.1.3（我）你的 MAC 地址」
  3. 局域网内所有设备都收到这个广播，但只有 192.168.1.5 响应
  4. 192.168.1.5 单播回复：「我是 192.168.1.5，我的 MAC 是 XX:XX:XX:XX:XX:XX」
  5. A 把结果缓存到 ARP 缓存表（用 arp -a 查看），下次直接用

⚠️ ARP 的安全隐患：ARP 没有身份验证机制。攻击者可以伪造 ARP 响应，声称自己就是网关的 IP，从而拦截所有流量——这就是 ARP 欺骗（ARP Spoofing），是中间人攻击的经典手法。

4. 以太网帧 —— 数据长什么样？

链路层传输的数据单元叫帧（Frame）。以太网帧是目前最主流的帧格式：

几个要点：

  • 类型字段——告诉接收方「数据部分装的是什么协议」，这样接收方知道该把 payload 交给 IP 模块还是 ARP 模块
  • MTU（最大传输单元）——数据部分通常最多 1500 字节。如果 IP 包超过这个大小，就需要分片（IPv4 由路由器分片，IPv6 由发送端分片或使用 Path MTU Discovery）
  • CRC 校验——接收方重新计算校验和，如果不匹配说明帧在传输中损坏了，直接丢弃（链路层不重传，由上层 TCP 负责）
  • 最短帧 64 字节——如果数据不足 46 字节，用 padding 补齐。这是为了确保在旧式共享介质中能可靠检测冲突
🔑 MTU 为什么重要：如果你的 IP 包是 2000 字节而 MTU 是 1500，IP 层必须切成两片。分片会消耗路由器和终端的 CPU，也增加了丢包风险（一片丢、整个包废）。这就是为什么 VPN 和隧道协议经常遇到 MTU 问题——额外的封装头吃掉了有效载荷空间。

5. 交换机 —— 智能帧转发

在链路层最核心的设备是交换机（Switch）。要理解它为什么是「智能」的，先看它的两个「笨」前辈：

集线器 (Hub)交换机 (Switch)
工作方式收到帧 → 广播到所有端口收到帧 → 只转发到目标 MAC 所在的端口
冲突域所有端口共享一个冲突域每个端口独立冲突域
带宽所有端口共享（如 100Mbps / N）每个端口独占带宽
双工半双工（不能同时收发）全双工（可以同时收发）
安全性所有主机都能看到所有流量主机只能看到发给自己的流量

交换机的自学习机制

交换机怎么知道目标 MAC 在哪个端口？它自己学。过程极其优雅：

Step 1: 初始状态

MAC 表为空。交换机刚启动，不知道任何主机在哪。

Step 2: 收到帧

A（端口 1）发帧给 B。交换机记下：A 的 MAC 在端口 1。但还不知道 B 在哪。

Step 3: 泛洪

不知道 B 在哪 → 泛洪（flooding）：向除端口 1 外的所有端口转发该帧。

Step 4: B 回应

B 收到帧后回帧给 A。交换机记下：B 的 MAC 在端口 3。现在知道双方位置了。

Step 5: 精确转发

后续 A ↔ B 的帧只在端口 1 和 3 之间转发，其他端口不受干扰。

Step 6: 老化

MAC 表条目有过期时间（通常 5 分钟）。过期后重新泛洪学习。这样主机迁移了也能适应。

这就是即插即用的力量——交换机不需要任何配置，插上网线就能工作。它不依赖任何路由协议，纯粹靠观察流量自学网络拓扑。这是互联网设计哲学「简单核心，复杂边缘」在链路层的体现。

🔌 交换机 vs 路由器：很多人混淆这两个设备。交换机工作在链路层（查 MAC 表转发帧），路由器工作在网络层（查路由表转发 IP 包）。交换机连接同一网络内的设备，路由器连接不同网络。

6. 共享介质问题 —— 谁先说话？

在现代交换式以太网中，每个设备独占一条链路到交换机，用全双工通信——不存在冲突。但在 WiFi 和旧式总线型以太网中，多个设备共享同一个通信信道。如果有人同时在同一个频率上发信号，信号会互相干扰——这叫冲突（Collision）。

CSMA/CD —— 以太网的解决方案（历史）

旧式以太网的规则叫 CSMA/CD（载波侦听多路访问 / 冲突检测）：

  1. 先听后说：发之前先听，信道空闲才发
  2. 边说边听：发送的同时也在监听，检测是否发生冲突
  3. 冲突后退：检测到冲突，停止发送，等一个随机时间再重试（二进制指数退避）

CSMA/CA —— WiFi 的解决方案（现实）

WiFi（802.11）用的是 CSMA/CA（冲突避免），因为无线环境下无法在发送的同时检测冲突（发送信号太强会盖过接收信号）：

  1. 先听后说 + 随机退避：空闲后还要等一个随机时间槽
  2. RTS/CTS 可选机制：发前先预约——「我要发 X 字节，请大家都安静」（解决隐藏节点问题）
  3. 确认机制：收到帧后回复 ACK。和以太网不同，WiFi 链路层就做确认和重传——因为无线环境丢包率太高，等 TCP 来重传效率太低
💡 为什么 WiFi 比有线慢？不仅因为物理速率，还因为：① 半双工（不能同时收发）② CSMA/CA 的退避开销 ③ 链路层 ACK 的开销 ④ 共享介质（你和邻居的路由器在争同一个信道）。100Mbps 的有线通常比 300Mbps 的 WiFi 体验更流畅。

7. 一个完整的局域网通信过程

把上面所有概念串起来——假设主机 A（192.168.1.3）想 ping 主机 B（192.168.1.5），它们连在同一台交换机上：

  1. A 查路由表：192.168.1.5 在同一子网 → 直接发，不需要网关
  2. A 查 ARP 缓存：如果不知道 192.168.1.5 的 MAC → 广播 ARP 请求
  3. 交换机泛洪 ARP 请求：交换机从端口 1 收到广播帧 → 泛洪到所有其他端口
  4. B 单播 ARP 响应：B 收到 ARP 请求，回复自己的 MAC。交换机看到目的 MAC 在端口 3 → 只转发到端口 3
  5. A 封装帧：源 MAC = AA，目的 MAC = BB，类型 = 0x0800 (IPv4)，payload = ICMP Echo Request
  6. 交换机转发帧：查 MAC 表 → BB 在端口 3 → 从端口 3 发出（其他端口不受影响）
  7. B 收到帧：CRC 校验通过 → 类型字段是 0x0800 → 把 payload 交给 IP 模块 → IP 模块再交给 ICMP 模块 → B 回复 ICMP Echo Reply

整个过程，交换机在后台静默地学习和转发，完全没有改变帧的内容。这就是链路层的完整图景。

📚 补充：VLAN 与数据中心网络

VLAN（虚拟局域网）—— 在一台交换机上隔离多个网络

你已经知道：交换机根据 MAC 地址转发帧，默认情况下所有端口都在同一个广播域内——ARP 广播会到达所有端口。这在大型网络中很糟糕：几百台机器的 ARP 广播互相淹没。

VLAN 解决的问题：在一台物理交换机上创建多个逻辑隔离的网络。

没有 VLAN：一台交换机 48 个端口 = 1 个广播域 = ARP 广播到达所有 48 个端口
有 VLAN：同一台交换机上 VLAN 10（端口 1-12 财务部）、VLAN 20（端口 13-24 工程部）、VLAN 30（端口 25-36 运维部）——ARP 广播只在各自的 VLAN 内传播

跨 VLAN 通信必须经过路由器——即使两台机器插在同一台交换机上，如果属于不同 VLAN，帧也不能直接转发。这既是隔离（安全），也是约束（需要路由）。

帧在进入交换机时被打上 802.1Q Tag（4 字节），包含 12 位的 VLAN ID（0–4095）。Trunk 端口可以承载多个 VLAN 的帧（帧带着 Tag），Access 端口只属于一个 VLAN（帧不带 Tag）。

数据中心网络 —— 链路层的工程巅峰

传统三层网络（接入层 → 汇聚层 → 核心层）在数据中心遇到了瓶颈：东西向流量（服务器之间，如微服务互调）远超南北向流量（客户端 ↔ 服务器）。

现代数据中心的典型拓扑是 Spine-Leaf（脊叶架构）：

        ┌─────────┬─────────┬─────────┐
        │ Spine 1 │ Spine 2 │ Spine 3 │   ← 每个 Leaf 连到所有 Spine
        └────┬─────┴────┬────┴────┬────┘
     ┌───────┼──────┬───┼─────┬──┼────────┐
     ▼       ▼      ▼   ▼     ▼  ▼        ▼
  ┌──────┐┌──────┐┌──────┐┌──────┐┌──────┐
  │Leaf 1││Leaf 2││Leaf 3││Leaf 4││Leaf 5│  ← 服务器直接连 Leaf
  └──────┘└──────┘└──────┘└──────┘└──────┘

任何两台服务器之间最多 2 跳（Leaf → Spine → Leaf），延迟可预测。配合 ECMP（等代价多路径）在 Spine 之间负载均衡。这就是为什么 Google 搜索的响应时间能控制在几十毫秒——数据中心的网络拓扑被精密设计过。

数据中心网络也大量使用 VXLAN（Virtual Extensible LAN）——把二层帧封装在 UDP 包里，在 IP 网络上延伸二层网络。这使得虚拟机可以在数据中心内自由迁移而不改变 IP 和 MAC。
