上一节(0001)讲了 epoll 为什么快。这一节把它写出来。写不出正好暴露概念缺口——这就是 gate 的意义。

两版骨架已放到 exercises/0002-epoll-echo/:

  • echo_server_py.py — Python selectors 版,先做这个
  • echo_server_c.c — C 裸 epoll 版,面试白板级

为什么先 Python 再 C

Python selectors 把 epoll 包了一层,不用管 struct epoll_event、不用管 fd 整数,10 分钟能跑通——先建立"多路复用 server 长什么样"的整体形状。然后 C 版把同一形状裸写一遍,fd 就是个 int,这才是面试要你白板写的。

Python 版 — 要填的 5 处

accept 出 conn 后,要告诉 epoll"以后帮我盯这个 fd 的可读事件"。

sel.register(conn, selectors.EVENT_READ, data=conn)

关键:data=conn 是你塞给 epoll 的私货。等会 sel.select() 返回时,它会原样还给你(key.data),这样你不用自己维护 fd→conn 的映射。这就是 epoll ev.data 字段的用途。

conn.sendall(data)

教学版用 sendall 省事。生产环境 socket buffer 满了 send 会 partial write,要监听 EVENT_WRITE + 缓冲未发完的数据——这是另一节课,先不管。

sel.register(sock, selectors.EVENT_READ, data=sock)

和 TODO 1 一样,只是这次 fd 是 listen socket。data 塞 sock 本身,待会用 key.fileobj is sock 区分"这是新连接"还是"这是数据"。

events = sel.select(timeout=None)

阻塞到任一 fd 就绪,返回 [(key, mask), ...]。只有就绪的,不遍历全部——这就是 0001 讲的"O(就绪数)"。

if key.fileobj is sock:
    accept_conn(sel, callback)
else:
    service_conn(sel, callback)

listen fd 可读 = 有新连接 → accept。conn fd 可读 = 有数据 → recv。同一个线程,同一个循环,靠 key.fileobj 分流。这就是"单线程扛多连接"的全部秘密。

跑起来验证

python3 echo_server_py.py
# 终端 2:
nc 127.0.0.1 9000
hello        # 应回显 hello
# 终端 3 (同时):
nc 127.0.0.1 9000
world        # 也回显 world, 互不影响

两个 nc 同时连、同时 echo = 多路复用成功 = gate 过。

C 版 — 同样的形状,裸写

填 5 处 TODO,对应 Python 的 5 步,只是没了抽象:

  1. epoll_create1(0) — 建 epoll 实例
  2. epoll_ctl(epfd, EPOLL_CTL_ADD, lfd, &ev) — 注册 listen fd
  3. epoll_wait(epfd, events, MAX_EVENTS, -1) — 等事件
  4. fd==lfd 分支:accept + set_nonblock + epoll_ctl ADD
  5. else 分支:read → >0 write 回去 / ==0 关连接 / <0 看 errno
gcc -O2 -Wall echo_server_c.c -o echo_server_c
./echo_server_c
C 版几个会卡你的点:struct epoll_event 的 .events 是位掩码(EPOLLIN | EPOLLET),.data.fd 是个 union,你存 fd 进去,返回时 events[i].data.fd 取回。LT 模式下 read 一次就行;切 ET 要循环 read 到 EAGAIN。

本节 gate:
1. Python 版:两个 nc 同时连都能 echo
2. C 版:同上,且 gcc -Wall 无 warning
3. 能口头讲清:为什么 data=conn / ev.data.fd 这字段存在(省掉自己维护 fd→对象映射)
4. 加分:把 C 版切到 ET,循环 read 到 EAGAIN,讲清不这么干会怎样(数据卡住)

概念检查(写代码前先答)

Q1. Python 版里,如果不传 data=conn,sel.select() 返回时你怎么知道是哪个连接?

Q2. C 版 epoll_wait 的第二个参数 events 数组和 MAX_EVENTS 各是什么角色?数组开太大有坏处吗?

Q3. 为什么 accept 出来的 conn_fd 也要 set_nonblock?LT 模式下不设会死吗?

答案(先想再展开)

Q1：key.fileobj 仍能拿到 fd/socket 对象(Python 自动维护),所以不传 data 也能用 key.fileobj 区分。但生产代码里一个 fd 上可能挂多种状态(待发缓冲、peer addr 等),data 让你把这些一起塞进去,省掉自己维护 dict。这就是 ev.data 的设计意图。

Q2：events 是你提供的输出缓冲,epoll_wait 把就绪事件填进去;MAX_EVENTS 是告诉它"最多填这么多"。返回值 n = 实际就绪数。数组开太大只是浪费一点栈/堆,没别的坏处;开太小会一次拿不完(下次 epoll_wait 还会返回剩下的,不会丢)。

Q3：非阻塞是为了 recv/read 没数据时返回 EAGAIN 而不是阻塞整个事件循环——一个慢连接把全 server 卡死。LT 模式下不设非阻塞也能跑(读到没数据时阻塞一下再返回),但会拖累其他连接;ET 模式下必须非阻塞,否则循环 read 到没数据时会阻塞死。所以无论如何都设。
