第 4 课：IP 网络层 —— 跨越网络的逐跳路由

传输层   TCP · UDP
◀ 网络层   IP · BGP · OSPF ◀ 本课
链路层   Ethernet · ARP · MAC
物理层   网线 · 光纤 · 无线电

你已经知道：链路层用 MAC 地址在同一个局域网里传帧，MAC 地址出不了局域网。那么问题来了——一个包要从北京的笔记本电脑发到旧金山的服务器，中间要经过十几个不同的局域网，怎么知道每一跳该往哪走？

这就是网络层（IP 层）的全部工作。

🎯 本课目标：理解 IP 地址的分层结构、CIDR 子网划分、路由表的查找逻辑、BGP/OSPF 两种路由协议的分工、NAT 的原理与代价，以及 traceroute 如何利用 TTL 探测路径。学完后你应该能解释「一个 IP 包从北京到旧金山，每一跳到底发生了什么」。

1. IP 地址 —— 分层的全球定位系统

和 MAC 地址不同，IP 地址是分层的。一个 IPv4 地址 32 位，分成两部分： 

192.168.1.5  =  11000000 10101000 00000001 00000101

如果前 24 位是网络号：
  └─────── 网络号 ───────┘└── 主机号 ──┘
  11000000 10101000 00000001   00000101

分层的含义：同一网络内的所有 IP，前缀一样。就像同一个小区的所有房间，地址都从「XX 路 XX 小区」开始，快递员不需要知道每个房间在哪，只需要知道怎么把货送到这个小区。

路由器的核心逻辑就是：只看网络号，不管主机号。一个路由器不用记住地球上每台设备的 IP，只需要知道「去某个网段该走哪个出口」。

CIDR：无类别域间路由

192.168.1.0/24 表示「前 24 位是网络号，后 8 位是主机号」。这就是 CIDR 记法。它能表示的地址范围：

1100 0000 1010 1000 0000 0000 01 0000 0101
■ 网络号（24 位 = 蓝色，路由器关心的）   ■ 主机号（8 位 = 土色，路由器不关心的）   范围：192.168.1.0 – 192.168.1.255

CIDR 的好处：路由表里不需要为 192.168.1.1、192.168.1.2……各写一条，一条 192.168.1.0/24 就覆盖了 256 个地址。这就是路由表能保持较小的秘诀——前缀聚合。

📍 关键对照：IP 地址是分层的（XX 网段 / XX 主机），所以路由表可以聚合，能支持全球规模。MAC 地址是扁平的，所以交换机 MAC 表没法聚合，只能支持局域网规模。这是整个互联网可扩展性的基础。

2. 路由表 —— 最长前缀匹配

每台路由器（以及你的电脑）都有一张路由表。核心逻辑极其简单：

目标 IP 包到了 → 查路由表 → 看哪个条目匹配 → 从对应接口发出去

路由表大概长这样（简化）：

目标网段下一跳出口接口
192.168.1.0/24（直连）eth0
10.0.0.0/810.0.0.1eth1
0.0.0.0/0192.168.1.1（网关）eth0

查表规则叫最长前缀匹配：一条 IP 包的目的地址可能匹配多条路由，选前缀最长的（最具体的）那条。

比如目标 IP 是 192.168.1.5：它同时匹配第 1 条（/24）和第 3 条（/0）。选第 1 条——/24 比 /0 更具体。0.0.0.0/0 是默认路由，匹配所有地址但优先级最低——相当于「实在不知道往哪走，就丢给网关」。

💡 查看你自己的路由表：终端里打 ip route 或 route -n。你会看到一条 0.0.0.0/0 指向你的路由器（通常是 192.168.1.1）——这就是你上网的「默认出口」。

3. 逐跳转发 —— 每一跳 MAC 变，IP 不变

这是最核心的图景。假设主机 A 在北京（192.168.1.5）ping 服务器 B 在旧金山（203.0.113.10）：

A
192.168.1.5
MAC: aa → 帧 → R1
（网关）
MAC: bb → 帧 → R2
（ISP）
MAC: cc → … → R-N
（最后一跳）
MAC: xx → 帧 → B
203.0.113.10
MAC: zz
源 IP: 192.168.1.5 → 目的 IP: 203.0.113.10（始终不变）
源 MAC: aa→bb 源 MAC: bb→cc 源 MAC: xx→zz

这个图里藏着网络层最重要的设计洞见：

  • IP 地址端到端不变——源 IP 和目的 IP 在整个旅程中始终如一。这就是"逻辑地址"的含义：它标识「最终目的地」的身份
  • MAC 地址逐跳重写——每一跳，帧的源 MAC 变成当前路由器的出口 MAC，目的 MAC 变成下一跳的 MAC。旧帧被拆掉，新帧被封装
  • 每台路由器查自己的路由表——R1 只看「去 203.0.113.0/24 应该走哪个出口」，完全不知道后面还有多少跳
🔑 这就是为什么分层这么重要：链路层只需要关心"当前这一跳怎么把帧发到隔壁"，网络层关心"穿过整个网络的完整路径"。两层各管各的，换 WiFi 或换光纤对 IP 层完全不可见。

4. 路由表从哪来？BGP 与 OSPF 的分工

路由表不会凭空出现。它来自路由协议。而这些协议分成两大类，对应两种完全不同的场景：

IGP（内部网关协议）EGP（外部网关协议）
代表OSPF, IS-ISBGP
作用范围一个 AS 内部AS 之间
类比公司内部怎么找到某个部门不同公司之间怎么交换邮件
核心目标找到最短/最快的路径找到符合策略的路径
典型规模几十到几百台路由器全球几十万个前缀

什么是 AS（自治系统）？

互联网不是一张扁平的大网。它是由成千上万个自治系统（AS）组成的。每个 AS 是一个机构管理的网络——中国电信是一个 AS（AS4134），Google 是一个 AS（AS15169），你的公司也可以有自己的 AS。

每个 AS 内部用 OSPF 管理自己的路由器（"我家内部怎么走"），AS 之间用 BGP 交换路由信息（"去你家的货从哪个口进"）。

BGP 不讲速度，讲策略

OSPF 像高德地图——自动算出最短路径。BGP 像一个政治外交系统：

  • 「中国电信说去 Google 的流量走这条链路」
  • 「但我们公司和中国联通有商业协议，优先走那条链路」
  • 「这个 AS 我们不信任，不收它的路由」

BGP 不是选最快的路，而是选符合商业关系和政策的路。这就是为什么有时候两台服务器物理上很近、但网络延迟很高——因为 BGP 策略把流量绕了远路。

5. NAT —— 一个"打补丁"的协议，却撑起了整个互联网

IPv4 地址只有 32 位——大约 43 亿个。全球设备早就超过这个数了。NAT（网络地址转换）是 1990 年代的应急方案，但现在每家每户都在用：

你的手机: 192.168.1.5 ─┐
你的电脑: 192.168.1.6 ─┤ 私有 IP（局域网内唯一，全球不唯一）
你的电视: 192.168.1.7 ─┘
                         │
                    ┌────┴─────┐
                    │  路由器   │  公网 IP: 123.45.67.89（全球唯一）
                    │  (NAT)   │
                    └────┬─────┘
                         │
                    互联网

NAT 路由器维护一张映射表：

内部 IP:端口外部 IP:端口目标
192.168.1.5:54321123.45.67.89:60001google.com:443
192.168.1.6:54322123.45.67.89:60002github.com:443

你的手机往 google.com 发包，源 IP 是 192.168.1.5——这在公网上无效。NAT 路由器把源 IP 替换成自己的公网 IP（123.45.67.89），并记下这个映射。回复到达时，再反向替换回来。

⚠️ NAT 的代价：破坏了端到端原则。有了 NAT，外部无法主动向内部设备发起连接（除非在 NAT 上手动配置端口转发）。这就是为什么 P2P 软件、VoIP、在线游戏经常需要 STUN/TURN 这类 NAT 穿透技术。

6. TTL 与 traceroute —— 防止包永远流浪

IP 包头里有一个字段叫 TTL（Time To Live）。每经过一个路由器，TTL 减 1。减到 0，路由器丢弃这个包，并回复一个 ICMP "Time Exceeded" 消息给源地址。

这个设计有两个用途：

  1. 防止路由环路——如果路由配错了形成环路，包不会永远转圈
  2. traceroute——故意利用 TTL 来探测路径上的每一跳

traceroute 的原理非常狡猾：

先发一个 TTL=1 的包 → 第一跳路由器 TTL 减到 0 → 路由器回复 "Time Exceeded"
                                        → 知道了第一跳是谁！
再发一个 TTL=2 的包 → 第二跳路由器 TTL 减到 0 → 路由器回复
                                        → 知道了第二跳是谁！
……依此类推，直到到达目的地

在你的终端试试：traceroute google.com（Linux/Mac）或 tracert google.com（Windows）。你会看到包经过的每一跳以及每跳的延迟。

7. 完整图景：一个 IP 包的旅程

把本课所有概念串起来——主机 A ping 谷歌的 DNS（8.8.8.8）：

  1. A 查路由表：8.8.8.8 不在本地子网 → 匹配 0.0.0.0/0 → 发给默认网关 192.168.1.1
  2. 链路层封装：ARP 拿到网关的 MAC，封装帧 → 发给交换机 → 到网关
  3. 网关（家用路由器）：拆帧，查路由表 → 匹配到 ISP 的路由 → NAT 把源 IP 从 192.168.1.5 改成公网 IP → 封装新帧发出去
  4. ISP 路由器：拆帧，查路由表 → OSPF 说去 Google 走这个出口 → 封装新帧发出
  5. ……跨越多个 ISP 和 AS……：BGP 在 AS 之间交换路由信息，确保每个 AS 知道怎么到 8.8.8.0/24
  6. 最后一跳路由器：拆帧 → 发现 8.8.8.8 在本网段直连 → ARP 拿到 8.8.8.8 的 MAC → 封装帧发出
  7. Google 的服务器：收到帧 → 校验通过 → 交给 IP 层 → 交给 ICMP → 回复 Echo Reply → 整条路径反着走一遍

每一跳：MAC 变、TTL 减 1、查路由表、转发。源 IP 和目的 IP 始终是 192.168.1.5（或被 NAT 改过的）和 8.8.8.8。这就是互联网最核心的转发机制。

🧩 对接链路层知识：还记得第 5 课里交换机「自学习、泛洪、老化」吗？路由器也在做类似的事，但在网络层——它交换的不是 MAC 信息，而是「去 X 网段走哪个出口」的路由信息。交换机关心的是一栋楼里的房间号，路由器关心的是跨城市的快递路线。

📚 补充：路由算法原理 —— 路由表从哪来

第 4 课讲了"路由器查路由表决定下一跳"，但路由表的内容是怎么算出来的？这由路由算法决定。两大类：链路状态（全局信息）和距离向量（邻居交换）。

Dijkstra 算法 —— 链路状态路由（OSPF 的核心）

每个路由器知道整张网络拓扑图（通过泛洪 LSA 获得），然后各自跑 Dijkstra 算法，算出去所有目的地的最短路径。

Dijkstra 的核心思想（贪心）：
1. 初始化：自己距离=0，其他节点未知
2. 选当前距离最小的节点，标记为"已确定"
3. 通过这个节点松弛它的所有邻居（如果经由我到邻居比你当前记录的距离更短，就更新）
4. 重复 2–3 直到所有节点确定

O(|V|²) 时间复杂度。OSPF 用的正是这个——因为一个 AS 内部路由器数量有限（几百台），全局拓扑已知，Dijkstra 算一遍很快。

Bellman-Ford / 距离向量 —— BGP 的数学基础

路由器不知道整张图的拓扑，只知道邻居告诉自己的距离向量（"我到 X 网段的距离是 Y"），然后更新自己的表。

Bellman-Ford 方程：
dx(y) = minv { cost(x, v) + dv(y) }
翻译：我到 y 的最短距离 = min( 我到每个邻居的距离 + 邻居到 y 的距离 )

「计数到无穷」问题 —— 为什么 RIP 被淘汰了

距离向量有一个经典 bug。假设 A—B—C 三个节点串连。A 和 C 之间的链路断了，B 告诉 A "我到 C 的距离是 2"（因为 B 还记着旧路由），A 更新自己为 3，B 看到 A 说 3 就更新自己为 4，A 再看到 B 说 4 就更新为 5……循环到无穷。

这就是为什么 RIP（基于距离向量）有"最大跳数 15"的限制——超过 15 就算不可达，强行打断无穷循环。OSPF 没有这个问题。

为什么 BGP 不用 Dijkstra？

OSPF（Dijkstra）BGP（路径向量）
知道全局拓扑？是（AS 内部）否（互联网太大，没人知道全貌）
优化目标最短路径符合策略的路径
规模几百台路由器全球几十万前缀
算法Dijkstra路径向量（类似 Bellman-Ford + 完整路径防环路 + 策略过滤）

BGP 不能跑 Dijkstra 有根本原因：没有人知道全球互联网的完整拓扑，也没有人有权为全局计算最优路径——每个 AS 是自治的，BGP 只交换可达性信息。
